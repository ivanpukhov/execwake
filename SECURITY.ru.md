# Политика безопасности

[English](SECURITY.md)

## Поддерживаемые версии

Исправления безопасности выпускаются для последнего опубликованного release
candidate. Старые альфа-версии можно использовать для воспроизведения проблемы,
но они не поддерживаются.

## Сообщение об уязвимости

Используйте [приватный отчёт GitHub](https://github.com/ivanpukhov/execwake/security/advisories/new).
Не создавайте публичный issue с описанием уязвимости.

Укажите версию ExecWake, дистрибутив и версию ядра Linux, минимальный способ
воспроизведения и ожидаемые последствия. Удалите из логов и снимков экрана
токены, учётные данные, приватные имена узлов, имена пользователей и посторонние
пути.

Не прикладывайте базу данных сессии ExecWake к публичному issue. Она может
содержать аргументы команды, пути к файлам, имена процессов и сетевые адреса
трассируемой команды. Если база нужна для приватного отчёта, сначала опишите её
содержимое и приложите минимально возможный пример.

К проекту относятся уязвимости в изоляции сборщика, работе с привилегиями,
локальном сервере отчёта, обработке враждебных файлов сессий, гарантиях
приватности и проверке релизов. Подозрительное поведение сторонней команды,
которое ExecWake корректно записал, само по себе не является уязвимостью
ExecWake.

Для обычных ошибок используйте форму bug report и
[диагностический чек-лист](docs/diagnostics.ru.md).
